# Family and patient app: final screen spec v1 (for sign-off, then handover to the developer)

Date: 2026-11-13. Decisions approved by the founder 2026-11-13. Not code. Nothing built or sent.
Built from: `AnugaCare_App_Navigation_and_Screen_Map.md`, `AnugaCare_Screen_Master_List.md` (screen IDs F1 to F37 are kept), `AnugaCare_Payment_Screens_Design.md`, `docs/design/tokens.md`, the October boards 04, 05, 07 and 14 in `docs/design/`, and the family code on `origin/main` (`apps/family_app`, loaded by `apps/anugacare_app`).
How to use: (1) accept or change the 9 decisions, (2) generate the boards in section 6 so the set matches the companion boards, (3) give the developer this file plus the boards. Images are direction only; this file is the specification.
Sister document: `Companion_Screens_FINAL_Spec_v1.md`. The two use the same sample people, times and visual style.

## 2. Rules for every family screen

- **Header:** logo header with language pill and help "?" on the five main tabs; back arrow plus title on every other screen. No notification count. No grey placeholder avatar.
- **Visit progress:** thin 9-step bar with the text "Step n of 9" and the step name. Family words: Booked, Companion on the way, Picked up, At the centre, Handed to centre staff, Session finished, On the way home, Home, Visit complete. These map one-to-one to the existing trip states.
- **Stopped visits:** `cancelled`, `no_show` and `issue_reported` replace the bar with a banner in plain words ("Cancelled", "Patient was not available", "Service issue") and a Help button.
- **Sample data (use everywhere):** account owner Anita (daughter); patient Ravi Rao; second family member Kiran (viewer); companion Suresh (first name only); centre City Dialysis Centre, Kukatpally (sample address); home 12 Lake View Road, Kukatpally; today Thursday 12 November 2026; pickup code 482 913.
- **Sample times:** pickup 7:00 am, at centre 7:25 am, handover 7:35 am, session finished 11:45 am, home 12:30 pm. Next visits Fri 13 Nov and Mon 16 Nov, 7:00 am.
- **Privacy:** records, bills and consents never appear on any companion screen. Billing and consent changes are owner-only. A viewer never sees a cancel, pay or upload action. The pickup code is shown only to levels the database allows, and only when the visit state allows it.
- **Pickup code:** the family taps "Get pickup code"; the app shows six large digits with the line "Give this code to the companion at the door. Only the newest code works." Never show a code that was not issued.
- **Visual richness (same as the companion set):** illustrated avatar on every card that names a person; icon in a soft circle on every info row; vertical timeline with icons and real recorded times; drawn route card on visit screens; centre card with a building icon. Never a moving car, ETA, countdown, notification count, rating or "Verified" badge.
- **Words:** "companion", never nurse. "Visit", not "trip", in family copy. Status always with a word. Buttons at least 56 px, tap targets 48 px, text 16 to 18 px, key facts 24 to 28 px on the patient view, works at 200% text, light and dark, English, Telugu and Hindi.
- **Money:** amounts and plan names come from data, never from code. Every board that shows a price carries a small "Sample prices" tag. The banner "Development build, synthetic data only" stays until production is authorised.
- **Every screen needs:** loading, error with retry, offline, and empty or denied where it applies (section 5).

## 5. States every screen must have

Loading; error with "Try again" (typed text is kept); offline banner "No internet. Your changes will not be saved"; empty (no patient: "Your patient is not set up yet. Call AnugaCare support."; no visits; no records; no bills; no updates); denied ("You do not have access to this"). Visit detail also needs: code not available yet, code issued, cancelled, patient not available, service issue. Request a visit needs: no package available, duplicate request, consent needed. Bill detail needs: paying, paid, payment failed. Add photo needs: uploading, failed, too large.
